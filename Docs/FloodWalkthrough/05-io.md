# Part 5 - `io.rs`: turning arrays into maps

File: `sar_science_processor/src/io.rs` (1670 lines)

The science engine works with numbers. A human needs files:

- **PNG** for quick previews and transparent map overlays.
- **GeoTIFF** for GIS tools (QGIS, GDAL, TiTiler) and acreage analysis.
- **GeoJSON** for vector polygons that Leaflet can draw and click.

This file writes all three, plus some InSAR/XYZ helpers that the flood path does not use.

## 2. `save_sar_image` (lines 9-119) - grayscale preview

This renders a complex radar image as a viewable grayscale PNG.

| Line(s) | Code | Plain English |
| :---: | :--- | :--- |
| 18-21 | signature | Input a borrowed complex image and an output filename. |
| 22-23 | `rows`, `cols` | Image size. |
| 26-29 | downsample factor | `max_dimension = 2048`. If the image is larger than 2048 in either direction, `factor = ceil(max / 2048)`. This keeps the preview small. |
| 31-32 | `out_rows`, `out_cols` | Integer division by `factor`. Any leftover edge pixels at the bottom/right are dropped from the preview. |
| 34-38 | log | Report the reduction. |
| 41-43 | accumulators | `num_finite` counts valid blocks; `log_intensity` will hold one value per output pixel. |
| 45-46 | output loops | For each output row/column. |
| 48-52 | block bounds | The input block starts at `out_r * factor`, and ends at most `factor` pixels later, clamped to the image edge. |
| 54-58 | inner loops | Sum the intensity (`re^2 + im^2`) of finite pixels and count them. |
| 60-67 | average/log | If at least one valid pixel, average the intensity and take `log10(mean + 1e-10)`. The tiny `1e-10` avoids `log10(0)`. Otherwise store `NaN`. |
| 70-73 | sort valid values | Copy finite log values into a vector and sort them. |
| 75-83 | percentiles | `p2` is the value at the 2nd percentile, `p98` at the 98th. Ignoring the extreme 2% makes the picture less washed out. Empty -> fallback `0..1`. |
| 84-85 | stretch range | `max(1e-6)` avoids dividing by zero. |
| 87-91 | log | Report the stretch. |
| 94-103 | quantize | Map each log value to 0-255: subtract `p2`, divide by the range, clamp to `0..1`, apply gamma, multiply by 255. `NaN` becomes black (`0`). |
| 106-110 | PNG buffer | Create an RGB image and set each pixel to `Rgb([v, v, v])` (equal red/green/blue = gray). |
| 112-113 | save | Write the PNG. |
| 114-116 | return | `Ok(())`. |

The preview is **not** the flood map. It is the raw radar picture, used for the dashboard's before/after panels.

### 2.1 `frost_filter` (lines 122-179)

| Line(s) | Idea |
| :---: | :--- |
| 123-179 | Frost speckle filter. For each pixel it looks at a local window, computes the local coefficient of variation (spread / mean), and blends the centre pixel with the local mean. This is used by the XYZ tile / display path, not by flood detection.

| Line(s) | Idea |
| :---: | :--- |
| 182-280 | Lee filter. Similar adaptive idea: estimate global noise, then blend each pixel with its neighbourhood based on local statistics. Smooths homogeneous areas; preserves edges. |

## 3. GeoTIFF in one paragraph

A TIFF is a header, some image data, and an **IFD** (Image File Directory): a list of 12-byte entries saying where things are and what they mean. A **GeoTIFF** adds tags:

| Tag | Name | Meaning |
| :---: | :--- | :--- |
| 33550 | ModelPixelScale | How many degrees one pixel covers. |
| 33922 | ModelTiepoint | Which ground coordinate pixel (0,0) maps to. |
| 34735 | GeoKeyDirectory | Declares the coordinate system, e.g. EPSG:4326. |
| 34264 | ModelTransformation | A full 4x4 transform (used by the f32 writer). |

The writers in this file build those bytes by hand. No GDAL, no Python, no extra crate.

| 777-784 | write | Create a buffered file, write all bytes, flush. |

Note: width and height are written as `SHORT` (`u16`). This is fine for AOI crops (hundreds of pixels) but would overflow for a full 16000-pixel scene. The flood path always writes a crop, so this is acceptable today.
