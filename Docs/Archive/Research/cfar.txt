Lightweight Non-ML Ship Detection Alternatives to CA-CFAR for SAR Imagery
Overview
Synthetic aperture radar (SAR) ship detection at scale typically uses some flavor of CFAR (constant false alarm rate), but standard CA-CFAR on pixel intensities is not always robust in heavy sea clutter, near coasts, or in dense traffic, and can be memory/CPU heavy if naively implemented. There are, however, several non-ML and very light-weight variants and alternatives—non-parametric CFAR, robust CFAR variants, and multi-scale anomaly detectors—that can be implemented in Rust on a single pass over the image using only local windows.

Current CA-CFAR in NISAR Pro
The existing NISAR Pro SAR processor implements a 2D CA-CFAR on the downsampled intensity image with guard and background windows and simple clustering. It computes a local mean of background cells in an annulus around the cell-under-test, multiplies by an analytically derived alpha factor based on desired Pfa, and declares a detection when intensity exceeds the threshold. This implementation is already parallelized over rows with Rayon and runs on a downsampled image (for example, 1780 × 1840), which keeps CPU and RAM usage reasonable while still providing usable detections.

However, standard CA-CFAR assumes exponential (or Rayleigh) clutter and can break in:

Heavy-tailed sea clutter where a few bright clutter samples dominate the mean.

Coasts and harbor areas with mixed land–sea clutter.

Crowded shipping lanes where neighboring ships fall into the reference window and raise the threshold.

Better CFAR Variants (Still Lightweight)
1. Nonparametric Wilcoxon CFAR
A recent line of work proposes a Wilcoxon nonparametric CFAR detector for SAR ship detection that does not assume any particular clutter distribution. Instead of modeling clutter as Gaussian, Rayleigh, Weibull, or alpha-stable, it uses order statistics (rank information) in the reference window and derives a closed-form expression for the false alarm rate of the Wilcoxon detector. Experiments on Radarsat-2, ICEYE-X6 and Gaofen-3 images show that Wilcoxon CFAR better maintains constant false alarm rate and improves detection of weak ships in rough seas compared to typical parametric CFAR schemes.

Implementation-wise, Wilcoxon CFAR only needs to:

Gather reference window samples around the cell-under-test.

Sort or partially sort them to compute a test statistic based on ranks.

Compare against a precomputed threshold for the desired Pfa.

This is still local-window based and parallelizable, and with small windows (e.g., 5×5 to 9×9) the per-pixel cost is dominated by small-array sorting, which is tractable in Rust in release mode on a downsampled image. No global statistics or large matrices are required.

2. Robust CFAR via Clutter Modeling (Alpha-stable, VIE-CFAR)
Several works propose improved CFAR based on better clutter modeling. One uses an alpha-stable distribution to model heavy-tailed sea clutter; it replaces the Gaussian assumption in traditional CFAR with an alpha-stable model that better fits impulsive, spiky clutter, producing fewer false alarms in ship detection. Another method, VIE-CFAR (Variable Index and Excision CFAR), incorporates a variability index and an excision step to censor multiple bright interferers from the reference cells before estimating clutter statistics.

VIE-CFAR has been shown to outperform classical CFAR detectors on ENVISAT and TerraSAR-X SAR data, particularly in dense traffic and sea states with multiple interferers. The algorithmic overhead is still local: compute variability indices in the reference window, discard cells above a variability threshold, and compute the threshold from the remaining cells.

Both alpha-stable CFAR and VIE-CFAR remain non-ML and can be implemented as drop-in replacements for CA-CFAR, with similar memory footprints and modest extra CPU cost due to more complex local statistics.

3. Superpixel-Level CFAR
Superpixel-level CFAR detectors segment the image into superpixels (small regions of homogeneous texture) and run CFAR at the region level instead of individual pixels. This approach tends to stabilize clutter statistics and reduces false alarms in heterogeneous sea states, at some cost in implementation complexity. Because decisions are made per superpixel instead of per pixel, the number of CFAR operations is reduced, which can offset the cost of superpixel segmentation.

A superpixel-CFAR design could fit NISAR Pro by:

Running a fast superpixel segmentation (e.g., SLIC) on the intensity image.

Computing a mean intensity per superpixel as the basic feature.

Running a 1D CFAR over superpixels along azimuth or range strips.

This is more RAM light than full 2D texture features and remains non-ML.

Anomaly-Based Non-ML Detection (AMTAD-Style)
Anomaly detection treats ships as local anomalies in sea clutter rather than as explicit targets with parametric models. The NISAR Pro code base already includes an "AMTAD" (adaptive multi-scale texture anomaly detection) algorithm which computes local variances at multiple scales (e.g., window sizes 3, 7, 15) and fuses them into an anomaly map via weighted variance and adaptive weights.

This AMTAD algorithm is fully non-ML and per-pixel computes only a few windowed sums, with weights tuned by a tanh function, making it computationally light and embarrassingly parallel. Thresholding the anomaly map and clustering detections can yield ship candidates, particularly for small or weak ships that stand out in texture rather than in pure intensity.

A hybrid detector can:

Run AMTAD on the intensity image to obtain an anomaly score map.

Use CFAR (CA-CFAR, Wilcoxon CFAR, or VIE-CFAR) on intensity, but only inside high-anomaly regions.

This significantly prunes the search space and reduces CFAR computations, saving CPU.

Integral-Image CFAR to Save CPU
Classic CA-CFAR in NISAR Pro currently loops over each cell and over all background cells explicitly, which is conceptually simple but computationally quadratic in window size. A known optimization is to use integral images (summed-area tables) to compute the sum and count in any rectangular window in constant time, dropping complexity from per-pixel O(W²) to O(1) after a single O(N) pre-pass over the image.

For a guard window and outer background window that are both rectangular, the background sum can be obtained as the difference of two rectangles in the integral image, and the mean is sum divided by number of cells. This significantly decreases CPU while using negligible extra RAM (one extra float array the size of the image).

Combining integral-image CFAR with downsampling and multi-threading provides a very fast implementation that can be more CPU-light than many ML models while retaining the probabilistic guarantees of CFAR.

Lightweight Local ML Options (If Needed)
The requirement is that any ML/DL must be 100% free, run locally, and be very light on CPU/RAM. Public SAR ship datasets like SSDD, HRSID, and DSSDD exist, and current state-of-the-art methods (e.g., AMANet, memory-augmented autoencoders) are relatively heavy. However, there are lighter options:

Use a tiny convolutional classifier (e.g., 3–5 conv layers, depthwise separable) that runs on small candidate patches extracted from a non-ML pre-detector (CFAR or AMTAD), acting only as a false-positive filter.

Run the classifier with 8-bit quantized weights and activations, using a small engine like ONNX Runtime or a custom Rust inference engine compiled with no GPU.

The DSSDD paper explicitly shows that a memory-augmented autoencoder can be used to remove false alarms from a two-parameter CFAR pre-detector. A much smaller network than theirs could be trained for a similar role based on open datasets and then embedded into NISAR Pro as an optional local module.

Even without training new models, one could experiment with off-the-shelf lightweight object detectors or segmentation models that have small backbones, but they tend to be less tailored to SAR and may not meet strict RAM/CPU constraints.

Recommended Design for NISAR Pro
Given the constraints (Rust, local execution, minimal CPU/RAM, non-ML preferred), a practical evolution path from current CA-CFAR is:

Replace or augment CA-CFAR with a robust variant such as Wilcoxon nonparametric CFAR or VIE-CFAR to improve robustness against heavy clutter and multiple interferers while remaining local and non-ML.

Implement integral-image based CFAR to reduce per-pixel compute from O(W²) to O(1), using one additional float image as the summed-area table.

Fuse AMTAD anomaly detection with CFAR: run AMTAD to get an anomaly map, then restrict CFAR to high-anomaly regions to cut down computation and focus on likely ships.

Optionally add a tiny local ML classifier that runs only on CFAR+AMTAD candidates to filter false positives, trained on open SAR ship datasets and executed in quantized form on CPU.

These changes keep the core of NISAR Pro's ship detection non-ML and efficient, while providing several avenues for higher accuracy without needing heavy GPUs or large neural networks.

Idea: “remove the brightest K reference cells” to avoid a few bright clutter spikes or nearby ships from inflating the background mean.

Because your current integral image only gives you sums, not sorted samples, you can:

Keep the integral‑image background sum as a first pass.

In the CFAR loop, when cut_val is near the threshold (e.g. within a factor 2–3), pay the extra cost of scanning the ring explicitly to find the top 1–2 brightest v_max, and subtract them:

// After computing bg_sum, bg_mean with integral image
if cut_val as f64 > threshold * 0.5 {
    // Slow path: refine background by excising top interferer(s)
    let mut max1 = 0.0_f32;
    let mut max2 = 0.0_f32;
    for rr in (r - bg_size)..=(r + bg_size) {
        for cc in (c - bg_size)..=(c + bg_size) {
            // skip guard region
            if (rr as isize - r as isize).abs() as usize <= guard_size &&
               (cc as isize - c as isize).abs() as usize <= guard_size {
                continue;
            }
            let v = owned[[rr, cc]];
            if !v.is_finite() || v <= 0.0 { continue; }
            if v > max1 { max2 = max1; max1 = v; }
            else if v > max2 { max2 = v; }
        }
    }

    let bg_sum_refined = bg_sum as f32 - max1 - max2;
    let n_bg_refined = n_bg - 2.0;
    if n_bg_refined > 0.0 {
        let bg_mean_refined = (bg_sum_refined as f64) / (n_bg_refined as f64);
        let threshold_refined = alpha as f64 * bg_mean_refined;
        if (cut_val as f64) <= threshold_refined || threshold_refined <= 0.0 {
            continue; // reject detection
        }
    }
}
